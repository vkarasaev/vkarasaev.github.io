# Загрузка сайта в GitHub: пошагово, без терминала и без веток

Никаких веток создавать НЕ нужно, терминал НЕ нужен. Всё делается мышкой на github.com.
Понадобится компьютер (с телефона неудобно) и 20-30 минут.

Главная идея безопасности: пока ты загружаешь файлы, старый сайт продолжает работать.
Новый включается одним переключателем в самом конце (шаг 5), тем же переключателем
выключается обратно, если что-то не так (раздел «Откат»).

---

## Шаг 0. Подготовка

1. Скачай архив сайта на компьютер и распакуй (двойной клик). Внутри лежат папки
   `src`, `public`, `docs` и файлы `package.json`, `package-lock.json`,
   `astro.config.mjs`, `README.md`, плюс скрытая папка `.github`.
2. Открой github.com, войди в аккаунт, зайди в репозиторий
   **github.com/vkarasaev/vkarasaev.github.io**. Там сейчас `index.html`, `CNAME`,
   `README.md` - твой работающий сайт. Мы его НЕ трогаем и ничего не удаляем.

## Шаг 1. Загрузить папку src

1. Кнопка **Add file** (справа сверху) → **Upload files**.
2. Открылось поле «Drag files here». Перетащи туда мышкой **папку `src` целиком**
   из распакованного архива. Дождись, пока прогрузится список файлов.
3. Внизу нажми зелёную **Commit changes**. Готово - появилась папка `src`.
   Старый сайт при этом работает как ни в чём не бывало.

## Шаг 2. Загрузить папку public

То же самое: **Add file → Upload files** → перетащи **папку `public`** →
**Commit changes**. Файлов много (сканы сертификатов, фото), загрузка идёт
минуту-две. Дождись, пока список перестанет пополняться, и только потом жми зелёную кнопку.

## Шаг 3. Загрузить docs и файлы из корня

**Add file → Upload files** → перетащи папку `docs` и следом, в то же поле,
четыре файла из корня: `package.json`, `package-lock.json`, `astro.config.mjs`,
`README.md` (можно выделить всё сразу). GitHub заменит старый README новым.
→ **Commit changes**.

## Шаг 4. Создать файл автосборки (копипастой)

Папку `.github` перетащить сложно (она скрытая), поэтому создадим файл руками:

1. **Add file → Create new file**.
2. В поле имени набери ровно (со слэшами, GitHub сам создаст папки):
   `.github/workflows/deploy.yml`
3. В большое поле вставь целиком:

```yaml
name: Deploy to GitHub Pages

on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: withastro/action@v3

  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - name: Deploy to GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v4
```

4. **Commit changes**.

## Шаг 5. Включить новый сайт (тот самый переключатель)

1. Вкладка **Settings** (в меню репозитория) → слева **Pages**.
2. Блок **Build and deployment** → **Source**: сейчас «Deploy from a branch».
   Поменяй на **GitHub Actions**. Сохранять отдельно не надо.
3. Запусти сборку: вкладка **Actions** → слева **Deploy to GitHub Pages** →
   справа **Run workflow** → зелёная **Run workflow**.
4. Появится строка с жёлтым кружком. Через 2-4 минуты кружок станет зелёной галочкой.

## Шаг 6. Проверить

Открой karasaev.com. Если видишь старую версию - обнови жёстко: Ctrl+Shift+R
(Windows) или Cmd+Shift+R (Mac), на телефоне - приватная вкладка.
Пройдись по: главная, /blog/, /credentials/, /therapy/, /en/.

---

## Откат: если что-то пошло не так (1 минута)

1. **Settings → Pages → Source** → верни **Deploy from a branch**,
   Branch: `main`, папка `/ (root)` → **Save**.
2. Через минуту-две karasaev.com снова отдаёт старый одностраничник
   (файл `index.html` мы не удаляли, он лежит в корне).

Потом пришли мне скриншот проблемы - починим и включим снова.

---

## После успешного запуска (не срочно)

1. Старый `index.html` в корне можно удалить недели через две, когда убедишься,
   что всё стабильно. Пока он лежит - откат мгновенный.
2. Все дальнейшие правки - по инструкции `docs/how-to/edit-single-page.md`:
   правишь один файл прямо на GitHub (карандаш → Commit), сборка сама, 2-3 минуты.
3. Разово: добавить сайт в Google Search Console и Яндекс.Вебмастер,
   отправить https://karasaev.com/sitemap-index.xml

## Частые вопросы

**Нужно ли что-то удалять перед загрузкой?** Нет. Старые файлы не мешают.

**GitHub пишет, что файлов больше 100.** Поэтому грузим папки по очереди (шаги 1-3).
Если упрёшься в лимит на `public` - раздели: сначала `public/certificates`, потом остальное.

**Что такое ветки и Pull Request?** Для этой задачи неважно. Всё делаем в main,
страховка - переключатель Source и нетронутый старый index.html.

**Сборка упала (красный крестик в Actions).** Кликни на запуск, сделай скриншот
красного шага, пришли мне. Сайт при этом не ломается: наружу смотрит прошлая версия.
