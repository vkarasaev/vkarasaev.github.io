# Как править одну страницу, не передавая весь сайт

Этот документ - входной билет для любой точечной правки. Схема всегда одна:

**[этот документ] + [файл страницы] + [замечания] → исправленный файл → заменить в репозитории → задеплоить.**

Больше ничего передавать не нужно, кроме случаев из раздела 4.

---

## 1. Что прислать в новый чат

1. **Этот файл** (`edit-single-page.md`) - он объясняет ассистенту устройство сайта.
2. **Файл страницы** - какой именно, смотри таблицу в разделе 2.
3. **Замечания** - обычным текстом: «поменяй заголовок на...», «убери блок FAQ про деньги», «цена теперь 6000». Скриншот с пометками тоже работает.

На выходе получишь готовый файл. Что с ним делать - раздел 5.

## 3. Где живут цифры и контакты (правится ОДНИМ файлом)

Телефон, почта, Telegram, цена сессии, расписание, метро, ссылки на каналы, статистика главной - всё в **`src/data/site.ts`**. Если правка про «поменять цену/телефон/расписание везде» - достаточно прислать только этот файл. Страницы подтянут значения сами.

Исключения (значения прописаны текстом, а не из site.ts): цена и даты группы - в файле лендинга группы; цены на /premium/ - в файле премиума; EN-расписание (CET) - в EN-файлах. Это указано в комментариях внутри файлов.

## 4. Когда нужен второй файл

- **Правка затрагивает внешний вид** (цвета, отступы, шрифты, вид карточек): добавь `src/styles/inner.css` (внутренние страницы) или `src/styles/main.css` (главная).
- **Правка цифр/контактов**: добавь `src/data/site.ts` (см. раздел 3).
- **Подписи сертификатов**: добавь `src/data/credentials.ts`.
- **Новая статья**: файл не нужен - достаточно текста статьи и даты; ассистент соберет `.md` по шаблону из этого документа (раздел 6).
- **Тон и голос**: если правка про переписывание текста, полезно приложить `docs/07-контент-и-голос.md` (голос, факт-лист). Не обязательно - правила ниже покрывают главное.
- **Меню/футер**: добавь `src/layouts/Page.astro`.

Если сомневаешься - пришли только страницу и замечания. Ассистент скажет, чего не хватает.

## 5. Что делать с исправленным файлом

1. GitHub → репозиторий `vkarasaev/vkarasaev.github.io` → найди тот же файл по пути из таблицы.
2. Кнопка-карандаш (Edit) → вставь новое содержимое целиком → Commit changes.
   Надежнее - через ветку и Pull Request, но для правки текста можно и напрямую в main.
3. Вкладка Actions: дождись зеленого «Deploy to GitHub Pages» (2-3 минуты).
4. Обнови страницу на karasaev.com (иногда с Ctrl+Shift+R / жестким обновлением).

Откат любой правки: History файла → Revert, либо восстановить прошлую версию тем же способом.

## 6. Правила, которые ассистент обязан соблюдать (передаются этим документом)

1. **Только дефис «-»**. Длинное тире (em-dash) запрещено везде: тексты, код, атрибуты. Проверить файл перед выдачей.
2. **Стек**: Astro, статика. В файлах страниц: сверху между `---` - код (frontmatter), ниже - разметка. Править обычно нужно только разметку и тексты; код трогать лишь по необходимости.
3. **Стиль**: Premium Dark. Токены цветов - CSS-переменные (`var(--gold)`, `var(--text)`...), не хардкодить новые цвета. Существующие классы: `.prose`, `.spec`/`.spec-row`, `.meta-line`, `.faq`, `.cta-final`, `.cert-card`, `.post-card`. Новые страницы и блоки собираются из них.
4. **Цифры и контакты** - из `src/data/site.ts`, не дублировать текстом (кроме исключений из раздела 3).
5. **Голос**: первое лицо, короткие фразы, без канцелярита, без мотивационных концовок, без «команды профессионалов». Мат допустим только в статьях блога, на продуктовых страницах - нет.
6. **Статья блога** - Markdown-файл в `src/content/blog/ru/` (или `en/`) c frontmatter:

```yaml
---
title: "Заголовок"
description: "1-2 предложения для списка и SEO."
date: 2026-07-07
lang: ru            # опустить для ru; en - для английской
categories: ["выгорание"]
tags: ["выгорание", "работа"]   # до 4
source_channel: telegram        # telegram | b17 | dzen | vc | original
source_url: ""                  # ссылка на оригинал, если есть
cover: ""                       # /images/photo/... , опционально
featured: false                 # true = блок «Избранное»
---
Текст статьи в Markdown. Разделитель между смысловыми блоками: строка ***
```

   Имя файла = slug = латиница-с-дефисами (`novaya-statya.md`). URL станет `/blog/novaya-statya/` и меняться не должен.
7. **Изображения**: класть в `public/images/photo/`, в тексте ссылаться как `/images/photo/имя.jpg`. Размер до ~1200px по длинной стороне, alt-текст обязателен.
8. **Не ломать URL**: адреса страниц зафиксированы; переименование только с редиректом (это отдельная задача, не точечная правка).
9. **Скрытые страницы** (/premium/ и будущие /lp/...): `noindex={true}` в Page, не добавлять в меню; из sitemap они исключаются автоматически (фильтр в `astro.config.mjs`).
10. **Ассистент возвращает файл целиком** (не диff), с сохранением комментариев в начале файла, и коротко перечисляет, что изменил.
